# BuildFlow Pro
## Component Rules v1.0

## Purpose

This document defines reusable design components for BuildFlow Pro.
It translates the Design Bible into production rules so AI tools and designers create consistent slides.

BuildFlow Pro must feel like an engineering consultancy communication system, not a generic presentation template.

---

# 1. Global Slide Framework

## Canvas
- 16:9 PowerPoint format
- 13.333 x 7.5 inch canvas
- 12-column grid
- Consistent header and footer system

## Every content slide must contain:

1. Eyebrow / module label
2. Slide title
3. Main information area
4. Supporting visual or data element
5. Footer system

---

# 2. Cover Component

## Purpose
Create premium first impression.

## Structure

- Dark Charcoal background
- Bottom-left text alignment
- Large title
- Small project metadata
- Blueprint technical linework as background texture

## Rules

DO:
- Use strong typography
- Use negative space
- Use technical visual language

DO NOT:
- Use construction stock photos
- Use generic building renders
- Use decorative effects

---

# 3. Section Divider Component

## Purpose
Separate major modules.

## Structure

Elements:
- Large module number
- Module title
- Short descriptor
- Thin Blueprint Blue accent line

Example:

03
CONSTRUCTION
METHODOLOGY

---

# 4. Text + Content Component

Used for:
- company overview
- project summary
- explanation slides

Structure:

Left:
- title
- short narrative

Right:
- supporting data
- visual element

Rules:
- Avoid large paragraphs
- Use concise professional language
- One slide = one message

---

# 5. Capability Card Component

Used for:
- services
- capabilities
- technical areas

Structure:

Card:
- Icon top-left
- Capability title
- One sentence description

Rules:
- Maximum 6 cards per slide
- Use Concrete Gray card background
- Use Blueprint Blue only for emphasis

---

# 6. Process Diagram Component

Used for:
- construction lifecycle
- methodology
- workflow

Structure:

Horizontal flow:

01 → 02 → 03 → 04 → 05

Rules:
- Native editable shapes only
- Circular numbered nodes
- Thin connector lines
- No flattened images

---

# 7. Timeline Component

Used for:
- project schedule
- milestones

Structure:

- Horizontal timeline
- Phase blocks
- Milestone markers
- Duration labels

Rules:
- Keep simple
- Avoid complex Gantt charts
- Highlight only important milestones

---

# 8. KPI Dashboard Component

Used for:
- project control
- performance reporting

Structure:

3-4 KPI cards:

Metric number
↓
Metric label
↓
Trend indicator

Rules:
- Large numbers
- Minimal decoration
- Data first

---

# 9. Risk Matrix Component

Used for:
- HSE
- project risk
- mitigation planning

Structure:

5x5 matrix:

Likelihood
x
Impact

Rules:
- Green = positive/control
- Amber = attention
- Red = risk

Colors have meaning, never decoration.

---

# 10. Technical Diagram Component

Used for:
- construction methodology
- engineering explanation

Examples:
- workflow
- sequence diagram
- organization chart
- logistics flow

Rules:
- Must be understandable in 5 seconds
- Prefer simple geometry
- Must remain editable

---

# 11. Data Table Component

Used for:
- comparison
- scope matrix
- responsibility matrix

Rules:

Header:
Charcoal background + Warm White text

Body:
Warm White / Concrete Gray alternating rows

Avoid:
- dense spreadsheets
- unnecessary borders

---

# 12. Image / Illustration Placement

Illustrations support communication, not decoration.

Rules:

Use for:
- concept explanation
- human context
- technical storytelling

Avoid:
- realistic AI people
- generic construction scenes
- visual clutter

---

# 13. AI Production Rule

Before generating any component, AI must understand:

- Buyer
- Business purpose
- Slide objective
- Information hierarchy

Never generate visuals first.

The workflow:

Problem
↓
Message
↓
Layout
↓
Visual element
↓
Final slide

---

# Quality Check

Every component must answer:

1. Does this save the buyer time?
2. Does this look like engineering consultancy work?
3. Is the information clearer than a normal document?
4. Is the component reusable?
5. Can the buyer edit it?
